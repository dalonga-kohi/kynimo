# 0039 — Behaviors

- Status: accepted (format v7)
- Date: 2026-11-10

## Context

Keyframes describe motion that starts and stops. A lot of motion design is motion that never stops or that follows something else: a logo that breathes, a camera shake, a pendulum, a looping loader, a bounce after a move lands, a shadow that trails its object. After Effects does these with expressions (`wiggle`, `loopOut`, the inertial bounce snippet, pick-whip links). Kynimo can't take free-form expressions (ADR-0012), so the common ones become typed data, like text animators (ADR-0038).

Constraints: every frame must evaluate on its own (no state carried from earlier frames, no sampling of earlier frames to estimate velocity), randomness must come from the document, and a layer without behaviors must evaluate exactly as before.

## Decision

- **Format v7.** Every layer with a transform (all but audio, null layers included) gains `behaviors`, at most `MAX_BEHAVIORS` (16). An absent list means none, so layer bodies written for format 6 still validate (ADR-0024); the 6 → 7 migration writes `[]` into stored documents.
- **Shape.** A behavior is `{ id, name, enabled, property, type, …params }`. `id` is a `BehaviorId`, unique within its layer, generated as `behavior-N` from the seeded counter when an op omits it. `property` is one of the transform properties (`anchorPoint`, `position`, `scale`, `rotation`, `skew`, `opacity`). Other properties can join later as new `property` values. Disabled behaviors are skipped by evaluation but still validated (a disabled link still counts for cycles).
- **Value kinds.** Values that add to a property have the property's kind: a number for `rotation`, `skew` and `opacity`, `[x, y]` for `anchorPoint`, `position` and `scale`. The project check refuses a mismatch with the expected kind in the message.
- **Types.**
  - `wiggle` — `frequency` (animatable, wiggles per second, ≥ 0), `amplitude` (animatable, property kind), `octaves` (integer 1–8), `seed` (integer 0 … 2³²−1), and `linked` (boolean; vector properties only: both axes take the same noise, scaled by each axis's amplitude, which gives uniform scale wiggle). Value noise: for octave `o`, `x = t · frequency · 2ᵒ`, lattice values at `floor(x)` and `floor(x) + 1` from an integer hash of (seed, axis, octave, lattice index), blended by the quintic smoothstep `u³(u(6u − 15) + 10)`. Octaves are weighted `0.5ᵒ` and the sum is divided by the total weight, so the offset never exceeds `amplitude`. The hash uses only integer arithmetic (`Math.imul`, shifts), takes the lattice index as two 32-bit words so very long times don't collide, and is pinned by a test with exact values.
  - `oscillate` — `frequency` (animatable, Hz, ≥ 0), `amplitude` (animatable, property kind), `phase` (degrees), `waveform` (`sine`, `triangle`, `square`, `sawtooth`). With `θ = 2π · frequency · t + phase · π/180`: sine `sin θ`, triangle `(2/π) · asin(sin θ)`, square `sin θ ≥ 0 ? 1 : −1`, sawtooth `2 · frac(θ / 2π) − 1`.
  - `loop` — `direction` (`in` before the first keyframe, `out` after the last), `mode` (`cycle`, `pingpong`, `offset`, `continue`) and `span` (integer ≥ 0: how many segments at that end are looped, 0 = all). With the looped range `[s, e]` and `P = e − s`, `out` at frame `f > e`: cycle samples `s + (f − s) mod P`; pingpong reflects within `2P`; offset samples like cycle and adds `floor((f − s) / P) · (value(e) − value(s))`; continue is `value(e) + v · (f − e) / fps` with `v` the incoming velocity at the last keyframe. `in` mirrors it before `s` (continue uses the outgoing velocity at the first keyframe). Frames stay integers. A loop on a property with fewer than two keyframes does nothing; `describe_motion` says so.
  - `inertia` — `amplitude` (≥ 0, seconds), `frequency` (Hz, > 0), `decay` (per second, ≥ 0). From each keyframe after the first, until the next one: `offset = v · amplitude · sin(2π · frequency · t) / e^(decay · t)`, with `t` the seconds since that keyframe and `v` the velocity the track arrived with. It keeps going after the last keyframe, which is the usual use (a move that lands and settles).
  - `link` — `source: { layer, property }`, `multiply` (number), `offset` (property kind), `delay` (frames, ≥ 0). The property becomes `source × multiply + offset`, with the source read at composition frame `f − delay` (follow with lag). The source is a layer of the same composition (the same layer is allowed, with another property) with a property of the same kind. It reads the source's resolved value, behaviors included, in the source's own parent space, not world space. Cycles over (layer, property) are refused whatever the delays, like parenting; so is a source in another composition, at op time and in the project check. `precompose` refuses to split a link from its source, as it does for mattes.
- **Velocity, analytically.** A segment's velocity at an end is `(to − from) × slope / duration` with the duration in seconds, and `slope` the easing's derivative there: 1 for linear; 0 for hold and spring (a spring arrives and leaves at rest); for a bezier, `(1 − y2) / (1 − x2)` at the end and `y1 / x1` at the start, 0 when `x` is 0 there and `y` doesn't move, capped to ±10. A position segment on a spatial path uses the path's end tangent times its length. Nothing samples another frame.
- **Order per property**, fixed whatever the list order: (1) the base track, sampled at the frame a loop maps to; (2) plus inertia; (3) a link replaces the result; (4) plus each enabled `oscillate` and `wiggle` in list order; (5) the existing domain clamps (opacity 0..1, skew ±85). At most one link, one inertia and one loop per direction per property; a property with a link can't also have a loop or inertia, since the link would hide them.
- **Separate position.** When position is split into X and Y tracks, loop and inertia work on each axis's own keyframes, as separated dimensions do in After Effects. A `continue` loop has no remapped frame, so inertia reads the frame as it is.
- **A link budget.** A step is one (layer, property, frame) value computed because a link asked for it; memo hits are free. One `evaluateFrame` call may take at most `MAX_FRAME_LINK_STEPS` (100 000) steps across all compositions, charged before the work and refused with an error that says to shorten link chains or use fewer delayed links. Undelayed chains cost one step per link; a chain of N links with delays touches about N²/2 values when every layer of it is drawn, which the budget bounds.
- **Time.** `t` is layer time in seconds: `(frame − startFrame) · den / num`. Animated `frequency` changes phase abruptly, as in After Effects; presets keep it constant.
- **Operations.** `addBehavior { layer, id?, behavior, index? }`, `updateBehavior { layer, behavior, set }` (any fields but `type`, which is refused with "remove and add a new behavior"), `removeBehavior { layer, behavior }`, mirroring the mask ops. Removing a layer that is a link source fails project validation with a message naming the linking layer, like a track matte source.
- **Surface.** `describe_motion` lists each behavior as one line ("wiggle position ±[20, 0] at 2 Hz, 2 octaves, seed 7"). The capability manifest lists the five types as supported and states `MAX_BEHAVIORS`. The `add_behavior` intent tool and behavior presets come with the intent tools.

## Consequences

- Breathing, shake, pendulum, looping loaders, landing bounces and trailing followers are data an agent can write in one op, and any frame still evaluates alone.
- Links create cross-layer dependencies inside a composition. Evaluating a frame resolves each (layer, property, frame) once per call. Delayed chains grow quadratically with their length, so the link budget, not the layer count, is what bounds them.
- The noise function, the velocity rules and the loop formulas are ours. If imported After Effects projects (v1.x) disagree, the engine changes, not the format.
- Not settled: behaviors on properties other than the transform (shape, mask and text properties), links across compositions, and expression-like math (`multiply` by another property).
