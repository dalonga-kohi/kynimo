# 0045 — Built-in 2D shaders: generator layers and looks

- Status: accepted
- Date: 2026-11-11

## Context

ADR-0012 puts code in the scene graph only as typed nodes, ADR-0016 gives the compositor its WebGL2 passes and ADR-0021 requires a float64 twin of every GPU pass. ADR-0042 shipped the first effect stack. The roadmap's next item is a built-in library of 2D shaders: backgrounds and textures that are layers, and looks that are effects. Custom GLSL (M6) should extend the same shape, not replace it. Everything here has to stay deterministic: same document and frame, same pixels, on SwiftShader and in the float64 reference.

## Decision

- **Scene format 9.** `SCENE_FORMAT_VERSION = 9`. The 8 to 9 migration changes only the version, because every addition is a new type.
- **Typed, no generic shader id.** A new drawn layer `generator` (`width`, `height`, `generator`) holds a `GeneratorSchema` union of four kinds, and five new effect types extend the effect union. There is no `{ shader: "id", params: {} }` form. When custom GLSL arrives in M6 it adds a custom variant to the same two unions, with declared typed uniforms.
- **Generators** (every field required, animatable unless noted): `gradient` (`kind` linear, radial or conic; `start`, `end`, each axis ±65536 (`MAX_GENERATOR_POINT`, clamped after easing); `stops`, 2 to 16, non-decreasing offsets, equal length across keyframes), `noise` (`seed`; `scale` 8 to 4096 px per cell; `octaves` 1 to 6, constant; `evolution` ±1000; `offset` ±8192; `low`, `high`), `pattern` (`kind` stripes, checker, dots or grid; `size` 2 to 2048; `thickness` 0 to 1; `angle` ±3600 degrees clockwise; `offset` ±8192; `foreground`, `background`), `aurora` (`seed`; 2 to 4 `colors`; `evolution` ±1000, one unit is one full loop; `softness` 0 to 1). A generator layer is placed, masked, matted, blended and given effects like a solid, and can be a track matte source.
- **Looks:** `vignette` (`amount`, `radius` 0 to 2, `feather` 0.01 to 2, `color`), `grain` (`amount`, `size` 1 to 8 constant, `seed`, `animated`, `monochrome`), `chromatic-aberration` (`amount` 0 to 32 px at the raster edge), `posterize` (`levels` 2 to 32), `scanlines` (`amount`, `spacing` 2 to 64, `thickness`, `offset` ±8192, `color`).
- **`setGenerator`.** `{ op: "setGenerator", layer, generator }` replaces a generator layer's body and fails on any other layer type. It is reached through `apply_ops` and the script SDK like every operation. Generators are added with `add_layer` (or `apply_ops` `addLayer`) and edited with `setGenerator`; looks go through the existing `add_effect`. There is no new MCP tool.
- **Trig and seeded values on the CPU.** The engine resolves everything that needs `sin`, `cos` or a seed in float64 and hands the shader plain numbers: the pattern's rotation as `[cos, sin]`, the aurora's blob points and sigma (from `hashWords`, integer frequencies 1 to 3 so one `evolution` unit is an exact loop), the scanline offset modulo its spacing, the grain frame. The only GPU trig is `atan` in the conic gradient. The float64 reference rounds each value it would pass as a uniform with `Math.fround`, so both sides start from identical inputs.
- **Integer hashing.** `hashWords(seed, words)` (exported from `@kynimo/engine`) is murmur3 x86_32 over a fixed list of 32-bit words: one block step per word, `h ^= 4 * words.length`, the fmix finalizer, built on the same `murmurStep` as the behaviors' `hashLattice`. The GLSL twin uses `uint` math, where wrapping multiplication equals `Math.imul`. Signed values enter as their two's-complement bit pattern. A hash becomes a unit value as `h / 4294967295`. There is no `fract(sin(...))` hashing anywhere.
- **No GLSL `round`.** Its tie direction is implementation-defined; the shaders use `floor(v + 0.5)`.
- **Pixel positions** are centres: `p = (x + 0.5, y + 0.5)` for the integer texel `(x, y)`, the same `ivec2(gl_FragCoord.xy)` the effect pass already used.
- **Hard edges are box-filtered.** A shared helper `band(x, halfWidth, period)` is the coverage of a one-pixel box centred at `x` over periodic bands. Stripes, grid, checker and scanlines use it, so float32 against float64 never flips a whole pixel. Dots use `clamp(r + 0.5 - distance, 0, 1)`.
- **The maths, condensed.** Colours are straight sRGB mixed linearly and output premultiplied, like the existing effects.
  - Gradient: `d = end - start`; `t = dot(p - start, d) / |d|²` (linear), `|p - start| / |d|` (radial), or `atan2(cross, dot) / 2π` wrapped to 0..1, clockwise on screen from `d` (conic); clamped; piecewise-linear between stops, first or last colour outside them. A start-point guard: when `|d|² < 1e-12` the gradient is `t = 1` (no division by zero, no `atan(0, 0)`).
  - Noise: per octave `f = 2^o`, lattice point `(p - offset) / scale * f` with `evolution * f` as the third axis, trilinear value noise with the quintic fade, corner values `unit(hashWords(seed, [o, x, y, z]))`, fractal sum weighted `0.5^o` and normalised.
  - Pattern: `q` is the pixel relative to the layer centre and offset, rotated by the inverse of the clockwise angle; stripes `band(q.x, f·s/2, s)`, grid the union of the two axes, checker `band(·, s/2, 2s)` combined by exclusive-or, dots in a grid of period `s` with radius `f·s/2`; the colour is `mix(background, foreground, coverage)`.
  - Aurora: Gaussian-weighted average of the colours around the blob points, `w_i = exp(-(d_i² - d_min) / 2σ²)` (the smallest squared distance is subtracted so it never underflows), `σ = (0.1 + 0.4 · softness) · max(width, height)`.
  - Vignette: `smoothstep(radius, radius + feather, |(p - c) / c|)` scales `amount · color.a`. Grain: per-cell hash noise in ±0.5 times `amount`, a cell being `size` pixels, the same value in all channels when monochrome, a fixed frame when not animated. Chromatic aberration: red and blue sampled at `p ± o` bilinearly (as the drop shadow's shifted sample), `o` growing linearly from the centre to `amount` at the half of the longer edge; the shifted position is clamped to the edge texel centres (`[0.5, size - 0.5]` per axis), so the raster edge does not fringe towards transparent black (padding texels of a drawn layer are transparent, so those are unaffected). Posterize: `floor(v · (L - 1) + 0.5) / (L - 1)` with `L` rounded to an integer. Scanlines: `band(p.y - offset, thickness · spacing / 2, spacing)` scaled by `amount · color.a`.
  - **Looks are anchored to the unpadded raster.** Vignette, grain and scanlines work in the coordinates of the layer's own raster, not of the padded effect raster, so adding or animating a reaching effect (blur, glow, aberration) in the stack never moves them. The effect pass receives the stack padding `(padX, padY)` and the unpadded size; the vignette centre is `(W0/2 + padX, H0/2 + padY)` with half-size `(W0/2, H0/2)`, scanlines use `p.y - padY`, and grain cells are `floor((p - pad) / size)` with floor division, so padding texels get their own cells. For adjustment layers padding is 0 and the size is the composition.
  - Looks leave transparent pixels transparent and alpha unchanged, except chromatic aberration, which takes the largest alpha of its three samples.
- **Stepped cases.** Posterize is stepped by design, equal-offset gradient stops are a hard edge, and the conic gradient has a seam where `t` wraps. The GPU-versus-reference tests give these the tolerance the blend-mode tests already use: a channel may differ more only on pixels where nudging the input by 3/255 crosses a step, and alpha must match. The conic fixtures use a first colour equal to the last so the seam is not a step.
- **Cost.** `effectSamples` is 1 for vignette, grain, posterize and scanlines and 9 for chromatic aberration (three bilinear taps). A generator charges `width × height × samples` to the same 500 million sample frame budget as effects, naming the layer in the error: gradient 1, pattern 1, aurora one per colour, noise `8 · octaves`. Padding is now a per-effect reach: chromatic aberration adds `ceil(amount)` per axis.
- **Raster-pixel reservation.** A generator renders into a float target of its own size, so the frame planner reserves `width × height` against `MAX_FRAME_RASTER_PIXELS` (2^28) for each generator layer, a generator planned only as a matte source included, with the existing `RenderError` wording. A frame at the limit passes; one pixel over is refused before any GPU work.
- **GPU path.** A GENERATOR pass draws the source into an RGBA16F target of the layer's size; from there it follows the precomp-result path (our mips, mask, effects, placement), so generators reuse every downstream guarantee. The reference computes the same image in float64.
- **Measured.** GPU (SwiftShader, RGBA16F) against the float64 reference differs by at most 1/255 per channel for every generator and every look, on translucent, masked, transformed layers. Posterize's stepped pixels are excluded as above. The tests assert 2/255.
- **Fixes found on the way.** The effect padding and blur path treated every effect's `radius` as a blur radius; the vignette's `radius` is not one, and padded and blurred with it. `blurRadius(effect)` now answers only for blur, drop shadow and glow. In the script SDK, the generated type for the scene's `Generator` collided with the `Generator` global of the ES library, so the SDK declares it as `Generator2` (a reserved name, like the other renames there).
- **Manifest and instructions.** `get_capabilities` lists `generators` (all four render) and the five looks under `effects`, with the limits (stops, gradient point `limits.generators.gradientPoint`, aurora colours, octaves, scale, evolution, offset, pattern size, aberration, grain size, posterize levels, scanline spacing). The `shaders` unavailable entry becomes `custom_shaders` (custom GLSL arrives in M6); the token catalog stays M5 and the component and shader catalogs M6. The server instructions gain one line pointing at `add_layer` and `setGenerator` for generators and at `add_effect` for looks; `add_effect`'s description names the five new types.
- **Size budgets** (the existing deviation from ADR-0035, to be undone by the M8 compaction): the tool listing 77 to 78 KB, the `apply_ops` listing 14 to 15 KB, the capability manifest 8 to 9 KB and the project JSON schema 74 to 90 KB, all raised in the scene step for the generator layer and its union. The MCP step raised nothing further.
- **Reference scene** `shader-backgrounds`: a four-colour aurora, 50 % overlay noise, a dots card, a screen-blended spotlight, a title and an adjustment layer with vignette, animated monochrome grain, scanlines and slight chromatic aberration. Its `evolution` runs 0 to 1 over its 90 frames, so it loops.

## Alternatives considered

- **A generic shader id with JSON parameters.** Untyped parameters cannot be validated, retimed, staggered or described to an agent, and it would put free-form code one step from the document. Typed variants give schemas, ranges and `get_layer_schema` for free; M6 adds a custom variant to the unions.
- **CPU-rasterized generators.** Easy to make exact, but full-frame noise per frame in CanvasKit is slow and does not scale to 4K or to effects on top of it.
- **GPU trigonometry with a looser tolerance.** `sin` and `cos` differ between drivers, so a wide tolerance would hide real regressions and break cross-GPU previews; computing them on the CPU gives identical inputs.
- **An `add_generator` intent tool.** The listing is already over budget (ADR-0043) and `addLayer` plus `setGenerator` cover it; a tool can be added later without a format change.

## Consequences

- Backgrounds, textures and looks are ordinary, editable, retimable layers and effects, visible to `describe_motion` and the script SDK.
- Custom GLSL in M6 reuses the passes' input contract: the source texture, resolution, layer-local frame and a document-derived seed.
- Follow-ups:
  - Shader transitions (M6).
  - The conic seam and a conic start point at the layer origin are tested in the reference only, not on the GPU.
  - No preset uses the looks yet; a "film" or "retro" preset family could.
  - The listing and manifest budgets come back down with the M8 compaction.
